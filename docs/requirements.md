# Game Shift 本地游戏启动器需求文档

## 1. 文档信息

| 项目         | 内容                 |
| ------------ | -------------------- |
| 产品名称     | Game Shift           |
| 产品类型     | Windows 本地桌面应用 |
| 文档类型     | 产品需求文档（PRD）  |
| 当前产品版本 | v0.2.0               |
| 当前目标版本 | v0.2.1               |

## 2. 项目背景

PC 游戏通常分散安装在不同目录或来自不同平台。部分游戏不在 Steam、Epic 等统一平台内，用户需要手动进入安装目录查找 `.exe` 文件启动游戏。随着本地游戏数量增加，这种方式查找成本高、管理分散、启动路径难记。

Game Shift 旨在提供一个轻量的本地游戏启动器，通过扫描本地目录、统一维护游戏列表和一键启动能力，降低用户寻找和启动游戏的成本。

## 3. 产品目标

### 3.1 核心目标

- 统一管理本地游戏启动入口。
- 支持扫描本地目录并发现可启动的 `.exe` 文件。
- 支持用户确认导入、手动添加、编辑和移除游戏。
- 支持一键启动游戏，并记录最近游玩时间和启动次数。
- 核心游戏库数据全部保存在本地，基础管理和启动能力不依赖 Game Shift 官方后端服务。

### 3.2 非目标

MVP 阶段不做以下能力：

- 游戏商店
- 账号体系
- 云同步
- 社交系统
- 支付系统
- Steam / Epic / GOG 等平台账号整合
- 自动下载或安装游戏

## 4. 目标用户

### 4.1 主要用户

- 本地安装较多 PC 游戏的用户。
- 同时使用多个游戏平台，但希望有一个统一启动入口的用户。
- 保存了独立游戏、绿色版游戏、模拟器游戏或开发测试程序的用户。

### 4.2 用户诉求

- 快速找到本地游戏。
- 不想记住每个游戏的安装目录。
- 希望统一查看、搜索、收藏和启动游戏。
- 希望数据留在本地，不依赖云端服务。

## 5. 使用场景

### 5.1 首次使用

1. 用户打开 Game Shift。
2. 系统展示空状态，引导用户扫描目录或手动添加游戏。
3. 用户选择一个本地游戏根目录。
4. 系统递归扫描目录中的 `.exe` 文件。
5. 系统展示扫描候选列表。
6. 用户确认需要导入的游戏。
7. 系统保存游戏信息并展示在游戏列表中。

### 5.2 日常启动游戏

1. 用户打开应用。
2. 用户通过列表、搜索、收藏或最近游玩找到游戏。
3. 用户点击启动按钮。
4. 系统启动对应 `.exe`。
5. 系统记录最近启动时间和启动次数。

### 5.3 手动维护游戏

1. 用户手动添加游戏，选择 `.exe` 文件。
2. 用户填写或修改游戏名称、启动参数、工作目录等信息。
3. 系统保存后，游戏出现在列表中。
4. 用户可以后续编辑或从列表中移除该游戏。

## 6. 功能模块

当前需求覆盖以下模块：

| 模块         | 说明                                              |
| ------------ | ------------------------------------------------- |
| 游戏扫描模块 | 选择目录、递归扫描、过滤无效 `.exe`、生成候选列表 |
| 游戏导入模块 | 展示扫描候选项、支持勾选导入、处理重复数据        |
| 游戏库模块   | 本地游戏数据的新增、查询、编辑、删除              |
| 游戏启动模块 | 根据路径、参数和工作目录启动游戏                  |
| 游戏列表模块 | 展示、搜索、筛选、收藏、最近游玩入口              |
| 手动添加模块 | 用户手动创建游戏记录                              |
| 封面管理模块 | 本地封面发现、手动选择和可选的联网封面搜索        |
| 设置模块     | 管理扫描规则、数据路径和可选联网能力              |
| 应用更新模块 | 检查、提示、下载并安装可信的新版本                |
| 本地存储模块 | SQLite 数据表和数据访问封装                       |

## 7. 功能需求

### 7.1 游戏扫描模块

#### 7.1.1 选择扫描目录

用户可以选择一个或多个本地目录作为扫描根目录。

要求：

- 支持 Windows 文件夹选择器。
- 支持一次扫描多个目录。
- 用户取消选择时不触发扫描。
- 扫描目录需要记录到本地配置，便于后续再次扫描。

#### 7.1.2 递归扫描 `.exe`

系统递归扫描目录下的所有 `.exe` 文件。

要求：

- 只识别 `.exe` 文件。
- 扫描过程不能阻塞 UI。
- 扫描完成后展示候选列表，而不是直接全部入库。
- 扫描结果需要包含文件名、完整路径、所在目录、推断名称。

#### 7.1.3 默认过滤规则

系统需要过滤明确不是游戏入口的目录和程序，例如开发工具、运行库安装包、卸载器和崩溃上报程序。

- 文件名和路径匹配不区分大小写。
- 不能仅因路径包含 `bin`、`Binaries` 或 `Win64` 就排除程序。
- 明确无效的程序不进入扫描结果。
- 无法确定的程序保留在“其他可执行文件”中，由用户决定是否导入。
- 首版使用内置规则，不提供自定义排除配置。

#### 7.1.4 游戏名称推断

扫描导入时，系统结合扫描根目录、程序所在目录和 `.exe` 文件名生成默认游戏名称。

- `bin`、`x64`、`Win64` 等通用目录名不得直接作为游戏名称。
- 无法从目录结构得到有效名称时，使用 `.exe` 文件名去掉扩展名。
- 用户可以在导入前和导入后修改名称。

### 7.2 游戏导入模块

#### 7.2.1 候选列表

扫描完成后，系统展示候选游戏列表。

字段：

- 推断游戏名称
- `.exe` 文件名
- `.exe` 完整路径
- 所在目录
- 是否已存在

交互：

- 候选项分为“推荐游戏”“其他可执行文件”和“已存在”。
- 默认勾选未重复的推荐游戏。
- 其他可执行文件默认不勾选，用户可以展开并手动选择。
- 已存在的候选项默认不可重复导入。
- 用户可以调整所有未导入候选项的选择状态。
- 用户点击确认后才写入数据库。

#### 7.2.2 重复处理

重复判断规则：

- `exe_path` 是唯一键。
- 同一路径再次扫描时不重复创建记录。
- 如果已有记录被用户编辑过，扫描不得覆盖用户自定义字段。

### 7.3 游戏库模块

#### 7.3.1 游戏列表

展示所有已导入或手动添加的游戏。

要求：

- 默认按收藏优先、最近游玩时间倒序、创建时间倒序展示。
- 支持空状态展示。
- 支持刷新列表。
- 支持点击游戏查看详情。

展示字段：

- 游戏名称
- 图标或默认占位图
- 收藏状态
- 最近游玩时间
- 启动次数

#### 7.3.2 搜索

用户可以通过关键词搜索游戏。

要求：

- 搜索范围包含游戏名称和 `.exe` 文件名。
- MVP 使用普通大小写不敏感匹配。
- fuzzy search 放到后续优化。

#### 7.3.3 分类筛选

MVP 支持以下筛选：

- 全部
- 收藏
- 最近游玩

V1 可扩展标签分类。

#### 7.3.4 编辑游戏

用户可以编辑已保存的游戏信息。

可编辑字段：

- 游戏名称
- `.exe` 路径
- 工作目录
- 启动参数
- 图标路径（可选，MVP 可不开放）
- 收藏状态

校验：

- 游戏名称不能为空。
- `.exe` 路径不能为空。
- `.exe` 路径必须指向 `.exe` 文件。
- 工作目录为空时默认使用 `.exe` 所在目录。

#### 7.3.5 移除游戏

用户可以从游戏库移除游戏。

要求：

- 只删除本地数据库记录。
- 不删除用户磁盘上的游戏文件。
- 删除前需要二次确认。

#### 7.3.6 启动程序失效处理

游戏被卸载、移动，或所在磁盘暂时不可用时，数据库中的游戏记录可能仍然存在，但原 `.exe` 路径已经失效。

要求：

- 系统不得因为启动程序暂时不存在而自动删除游戏记录。
- 用户尝试启动时，系统应明确提示启动程序不存在，并展示失效路径。
- 提示中提供“重新定位启动程序”“从游戏库移除”和“取消”操作。
- 重新定位后必须执行 `.exe` 文件存在性、文件类型和重复路径校验。
- 修复启动路径时保留游戏名称、收藏状态、封面、启动次数等现有资料。
- 对外置硬盘、移动存储或临时离线目录，路径恢复可用后应允许游戏恢复正常状态。
- 后续可在游戏卡片或列表中展示“启动程序不可用”状态，避免用户反复点击后才发现问题。

### 7.4 手动添加模块

用户可以不经过扫描，直接添加一个游戏。

表单字段：

| 字段        | 必填 | 说明                     |
| ----------- | ---- | ------------------------ |
| 游戏名称    | 是   | 用户自定义展示名         |
| `.exe` 路径 | 是   | 游戏启动程序路径         |
| 工作目录    | 否   | 默认使用 `.exe` 所在目录 |
| 启动参数    | 否   | 传递给游戏进程的参数     |

要求：

- 支持文件选择器选择 `.exe`。
- 选择 `.exe` 后自动填充默认游戏名称和工作目录。
- 保存前校验路径是否存在。
- 如果 `exe_path` 已存在，提示用户不可重复添加。

### 7.5 游戏启动模块

用户点击启动按钮后，系统启动对应游戏程序。

要求：

- 使用 Tauri 后端能力在 Windows 环境启动本地进程。
- 支持启动参数 `args`。
- 支持 working directory。
- 启动成功后记录 `last_play_time` 和 `play_count`。
- 启动失败时提示明确错误。

失败场景：

- `.exe` 文件不存在。
- `.exe` 路径不是可执行文件。
- 工作目录不存在。
- 权限不足。
- 系统拒绝启动进程。

### 7.6 收藏与最近游玩

#### 7.6.1 收藏

用户可以收藏或取消收藏游戏。

要求：

- 收藏状态持久化。
- 收藏游戏在默认排序中优先展示。
- 收藏筛选只展示已收藏游戏。

#### 7.6.2 最近游玩

系统在游戏启动成功后记录最近游玩时间。

要求：

- 最近游玩筛选只展示有启动记录的游戏。
- 按 `last_play_time` 倒序展示。
- 每次启动成功后 `play_count + 1`。

### 7.7 设置模块

基础设置项：

- 已保存的扫描目录列表。
- 默认扫描排除规则展示。
- 数据库位置展示。

扩展设置项：

- 自定义排除规则。
- 自定义排序方式。
- 数据导入 / 导出。
- 联网封面总开关、数据源说明和 API Key 管理。

### 7.8 游戏封面管理

#### 7.8.1 本地封面

系统优先使用本地能力完成游戏封面管理，不要求用户启用联网功能。

要求：

- 添加或编辑游戏时，系统可以从游戏目录自动发现本地封面。
- 用户可以通过文件选择器手动选择和更换封面。
- 待选封面先用于预览，保存游戏后才正式替换当前封面。
- 用户取消新增或编辑时放弃待选封面，已有封面保持不变。
- 封面必须经过格式、文件大小、图片尺寸和完整解码校验，再转码并写入本地缓存。

#### 7.8.2 联网封面启用

联网封面是默认关闭的高级可选能力，不是游戏库管理和启动流程的前置条件。

要求：

- 设置模块提供“联网封面”总开关，默认关闭。
- 未启用联网封面时，封面选择流程不展示联网入口。
- 用户打开开关后，设置页展开数据源说明和 API Key 配置。
- 首版使用第三方服务 SteamGridDB；SteamGridDB 与 Valve 或 Steam 无隶属关系。
- 用户需要通过 Steam 账号登录 SteamGridDB，并自行获取 SteamGridDB API Key。
- Game Shift 不得请求或保存用户的 Steam 密码、Steam Guard 验证码等 Steam 登录凭据。
- 用户主动执行联网搜索时，搜索词和 API Key 会发送给 SteamGridDB；本地游戏路径不得随请求上传。
- API Key 只保存在用户本机，不写入应用源码或安装包。
- 不建设 Game Shift 官方封面 API 网关，不要求用户注册或登录 Game Shift 账号。
- 只有联网开关已启用且 API Key 已保存时，封面选择流程才展示“联网搜索”入口。

配置状态分为：

- 未启用。
- 已启用但未配置。
- 已启用且可用。
- 已启用但配置异常。

“测试连接”与开关状态相互独立。临时断网、请求超时或第三方服务不可用时，不得自动关闭联网封面；第三方明确返回未授权时，系统标记配置异常并引导用户重新填写或验证 API Key。

关闭联网封面后：

- 立即隐藏联网入口并停止发起新的封面请求。
- 已经下载并缓存到本地的封面继续可用。
- 默认保留已保存的 API Key，方便用户再次开启。
- 设置页单独提供删除 API Key 的操作。

#### 7.8.3 搜索与选择

联网封面只在用户主动操作时发起请求，不在添加弹窗打开、游戏名称变化或目录扫描时自动搜索。

流程：

1. 用户在新增或编辑游戏时点击“联网搜索”。
2. 系统使用当前游戏名称自动执行首次搜索；用户可以修改搜索词后重新搜索。
3. 系统根据名称模糊搜索游戏，选择最佳匹配并查询该游戏的封面候选。
4. 候选区域展示当前匹配的游戏名称，并允许用户切换到其他游戏结果。
5. 系统展示当前匹配游戏的封面候选。
6. 用户手动选择一张封面；系统不得自动采用第一张候选。
7. 选中的网络封面只作为待保存预览，不立即覆盖已有封面。
8. 用户保存游戏时，系统下载、校验、转码并写入本地缓存。
9. 保存成功后替换游戏封面，并清理已经失效的旧缓存文件。

匹配和候选区域：

- 搜索栏和当前匹配游戏固定显示，封面候选区域独立纵向滚动。
- 系统突出展示当前匹配游戏，并始终使用一致的单选下拉交互查看和切换游戏结果。
- 其他游戏结果通过单选下拉列表纵向展示，不使用横向排列和横向滚动的标签按钮。
- 下拉列表高亮当前匹配，选择其他游戏后自动关闭，并重新加载对应封面候选。
- 重新搜索或切换匹配游戏后，封面候选区域回到顶部。
- 搜索词为空时清除旧匹配和旧封面，展示引导空状态，并提示用户输入游戏名称。

#### 7.8.4 失败回退与首版边界

- 无匹配结果时允许用户修改搜索词，并始终保留本地选择能力。
- 搜索失败时保留当前编辑内容，允许重试或改用本地图片。
- 下载失败时保留编辑弹窗、用户输入和原封面，不得写入不完整缓存。
- 首版不自动采用第一张封面。
- 首版不在目录扫描时批量匹配封面。
- 首版不在后台静默替换已有封面。
- 首版不同时搜索多个数据源。
- 首版不依赖 Game Shift 官方在线服务。

### 7.9 应用更新

应用需要提供版本检查和更新能力，减少用户反复前往 GitHub Releases 手动下载新安装包的成本。

#### 7.9.1 更新检查

- 设置页提供“自动检查更新”开关，默认开启。
- 用户可以关闭自动检查更新。
- 设置页始终提供“检查更新”按钮，不受自动检查开关影响。
- 开启自动检查后，应用在界面和游戏库完整加载后检查一次新版本。
- 更新检查不得阻塞应用启动或影响本地游戏库功能。

#### 7.9.2 发现新版本

自动检查和手动检查发现新版本后，使用同一个更新提示框展示：

- 新版本号。
- 发布日期。
- 更新内容。
- “立即更新”和“以后更新”按钮。

用户选择“立即更新”后开始下载和安装，并展示当前进度和状态；更新过程中不得重复触发操作。用户选择“以后更新”后关闭提示框并继续使用当前版本，下次启动时可以再次提醒。

#### 7.9.3 检查与更新结果

- 用户手动检查且没有新版本时，提示“当前已是最新版本”。
- 自动检查没有新版本时不打扰用户。
- 手动检查失败时展示错误信息，并允许重试。
- 自动检查失败时不弹出更新提示，不影响用户正常使用。
- 下载或安装失败时保留当前可用版本，并允许重试或前往 GitHub Releases 手动下载。
- 更新过程不得删除或损坏本地游戏库数据。

#### 7.9.4 首次迁移边界

- v0.2.0 及更早版本无法自动提示 v0.2.1，现有用户需要最后一次手动下载并安装 v0.2.1。
- 从 v0.2.1 开始，后续版本可以通过应用内更新完成升级。

## 8. UI 需求

### 8.1 主界面布局

主界面由三部分组成：

- 顶部：搜索栏、扫描按钮、手动添加按钮。
- 左侧：筛选导航，包括全部、收藏、最近游玩。
- 中间：游戏列表或网格。

要求：

- 首屏直接展示游戏库，不做营销式首页。
- 空状态提供扫描目录和手动添加两个主要入口。
- 操作按钮需要清晰区分主要操作和次要操作。

### 8.2 游戏卡片

游戏卡片包含：

- 游戏图标或默认占位图。
- 游戏名称。
- 最近游玩时间。
- 启动按钮。
- 收藏按钮。
- 更多菜单：编辑、移除、打开所在目录。

要求：

- 启动按钮是主要操作。
- 游戏名称过长时需要省略，不得撑破布局。
- 没有图标时使用统一默认样式。

### 8.3 扫描结果弹窗

扫描结果弹窗包含：

- 扫描目录信息。
- 推荐游戏和其他可执行文件数量。
- 分组的可勾选候选列表。
- 已存在项提示。
- 确认导入按钮。

### 8.4 添加 / 编辑游戏弹窗

表单包含：

- 游戏名称
- `.exe` 路径
- 工作目录
- 启动参数
- 游戏封面

要求：

- 必填项校验。
- 路径选择器。
- 封面选择、待保存预览和替换能力。
- 只有联网封面已启用且 API Key 已保存时，才展示联网搜索入口。
- 保存、取消按钮。
- 保存失败展示错误原因。

## 10. 技术栈

### 10.1 推荐技术栈

| 层级     | 技术                   | 用途                                          |
| -------- | ---------------------- | --------------------------------------------- |
| 桌面框架 | Tauri                  | 打包 Windows 桌面应用、访问系统能力           |
| 前端框架 | Vue 3                  | 构建桌面 UI                                   |
| 前端语言 | TypeScript             | 类型约束和可维护性                            |
| 构建工具 | Vite                   | 前端开发和构建                                |
| 后端语言 | Rust                   | Tauri command、文件扫描、进程启动、数据库访问 |
| 数据库   | SQLite                 | 本地持久化游戏数据                            |
| 状态管理 | Pinia                  | 管理游戏列表、筛选、扫描状态                  |
| UI 组件  | 自定义组件或轻量组件库 | 构建桌面应用界面                              |

### 10.2 技术选择说明

- Tauri 比 Electron 更轻，适合轻量本地工具。
- Rust 适合处理文件扫描、路径校验和进程启动。
- SQLite 不需要额外服务，适合本地持久化。
- Vue 3 + TypeScript 开发效率高，适合构建中小型桌面 UI。

### 10.3 关键 Tauri 能力

需要使用：

- 文件夹选择器
- 文件选择器
- 本地文件系统访问
- Tauri command
- 进程启动能力
- app data 目录读取

## 12. 非功能需求

### 12.1 性能

- 应用冷启动目标小于 1 秒。
- 扫描 1000 个 `.exe` 候选文件目标小于 5 秒。
- 扫描过程中 UI 不能卡死。
- 游戏列表 1000 条以内需要保持流畅。

### 12.2 稳定性

- 数据库读写失败需要提示错误。
- 启动游戏失败不能导致应用崩溃。
- 扫描目录失败需要跳过不可访问目录并记录错误。

### 12.3 安全性

- 应用不自动执行扫描到的 `.exe`。
- 用户必须主动点击启动才执行本地程序。
- 删除游戏记录不删除磁盘文件。
- 不上传本地游戏路径；除用户主动执行的联网搜索外，不上传游戏库信息。
- 联网封面只在用户主动搜索时请求第三方服务。
- SteamGridDB API Key 只保存在用户本机，不得打包固定密钥。
- Game Shift 不收集 Steam 登录凭据，也不提供依赖官方后端的封面代理服务。
- 应用只能安装经过来源校验的正式更新包。
- 更新失败不得破坏当前安装或删除本地游戏库数据。

### 12.4 本地化

- MVP 默认中文界面。
- 文案集中管理，后续可扩展英文。

## 13. MVP 验收标准

MVP 需要满足：

- 用户可以选择目录并扫描 `.exe`。
- 系统可以展示扫描候选列表。
- 用户可以确认导入候选游戏。
- 用户可以查看本地游戏列表。
- 用户可以搜索游戏。
- 用户可以手动添加游戏。
- 用户可以编辑游戏信息。
- 用户可以从列表移除游戏，但不删除磁盘文件。
- 用户可以点击启动游戏。
- 启动成功后可以记录最近游玩时间和启动次数。
- 游戏数据在关闭应用后仍然存在。
- 没有后端服务时应用可以正常使用。
