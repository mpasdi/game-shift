# Game Shift 本地游戏启动器需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | Game Shift |
| 产品类型 | Windows 本地桌面应用 |
| 文档类型 | 产品需求文档（PRD） |
| 当前版本 | v0.1 |
| 目标阶段 | MVP |

## 2. 项目背景

PC 游戏通常分散安装在不同目录或来自不同平台。部分游戏不在 Steam、Epic 等统一平台内，用户需要手动进入安装目录查找 `.exe` 文件启动游戏。随着本地游戏数量增加，这种方式查找成本高、管理分散、启动路径难记。

Game Shift 旨在提供一个轻量的本地游戏启动器，通过扫描本地目录、统一维护游戏列表和一键启动能力，降低用户寻找和启动游戏的成本。

## 3. 产品目标

### 3.1 核心目标

- 统一管理本地游戏启动入口。
- 支持扫描本地目录并发现可启动的 `.exe` 文件。
- 支持用户确认导入、手动添加、编辑和移除游戏。
- 支持一键启动游戏，并记录最近游玩时间和启动次数。
- 所有数据本地存储，不依赖后端服务。

### 3.2 非目标

MVP 阶段不做以下能力：

- 游戏商店
- 账号体系
- 云同步
- 社交系统
- 支付系统
- Steam / Epic / GOG 等平台账号整合
- 自动下载或安装游戏

## 4. 目标用户

### 4.1 主要用户

- 本地安装较多 PC 游戏的用户。
- 同时使用多个游戏平台，但希望有一个统一启动入口的用户。
- 保存了独立游戏、绿色版游戏、模拟器游戏或开发测试程序的用户。

### 4.2 用户诉求

- 快速找到本地游戏。
- 不想记住每个游戏的安装目录。
- 希望统一查看、搜索、收藏和启动游戏。
- 希望数据留在本地，不依赖云端服务。

## 5. 使用场景

### 5.1 首次使用

1. 用户打开 Game Shift。
2. 系统展示空状态，引导用户扫描目录或手动添加游戏。
3. 用户选择一个本地游戏根目录。
4. 系统递归扫描目录中的 `.exe` 文件。
5. 系统展示扫描候选列表。
6. 用户确认需要导入的游戏。
7. 系统保存游戏信息并展示在游戏列表中。

### 5.2 日常启动游戏

1. 用户打开应用。
2. 用户通过列表、搜索、收藏或最近游玩找到游戏。
3. 用户点击启动按钮。
4. 系统启动对应 `.exe`。
5. 系统记录最近启动时间和启动次数。

### 5.3 手动维护游戏

1. 用户手动添加游戏，选择 `.exe` 文件。
2. 用户填写或修改游戏名称、启动参数、工作目录等信息。
3. 系统保存后，游戏出现在列表中。
4. 用户可以后续编辑或从列表中移除该游戏。

## 6. 功能模块

MVP 包含以下模块：

| 模块 | 说明 |
| --- | --- |
| 游戏扫描模块 | 选择目录、递归扫描、过滤无效 `.exe`、生成候选列表 |
| 游戏导入模块 | 展示扫描候选项、支持勾选导入、处理重复数据 |
| 游戏库模块 | 本地游戏数据的新增、查询、编辑、删除 |
| 游戏启动模块 | 根据路径、参数和工作目录启动游戏 |
| 游戏列表模块 | 展示、搜索、筛选、收藏、最近游玩入口 |
| 手动添加模块 | 用户手动创建游戏记录 |
| 设置模块 | 管理扫描规则、数据路径等基础配置 |
| 本地存储模块 | SQLite 数据表和数据访问封装 |

## 7. 功能需求

### 7.1 游戏扫描模块

#### 7.1.1 选择扫描目录

用户可以选择一个或多个本地目录作为扫描根目录。

要求：

- 支持 Windows 文件夹选择器。
- 支持一次扫描多个目录。
- 用户取消选择时不触发扫描。
- 扫描目录需要记录到本地配置，便于后续再次扫描。

#### 7.1.2 递归扫描 `.exe`

系统递归扫描目录下的所有 `.exe` 文件。

要求：

- 只识别 `.exe` 文件。
- 扫描过程不能阻塞 UI。
- 扫描完成后展示候选列表，而不是直接全部入库。
- 扫描结果需要包含文件名、完整路径、所在目录、推断名称。

#### 7.1.3 默认过滤规则

默认排除明显不是游戏主程序的文件。

默认排除：

- `uninstall*.exe`
- `unins*.exe`
- `setup*.exe`
- `install*.exe`
- `update*.exe`
- `patch*.exe`
- `crashreport*.exe`
- `redist*.exe`
- `vcredist*.exe`

匹配规则：

- 文件名不区分大小写。
- 只匹配文件名，不匹配完整路径。
- MVP 阶段规则可以写死，V1 再提供配置界面。

#### 7.1.4 游戏名称推断

扫描导入时，系统自动生成默认游戏名称。

优先级：

1. 使用 `.exe` 所在目录名。
2. 如果目录名明显无意义，再使用 `.exe` 文件名去掉扩展名。
3. 用户可以在导入后手动修改名称。

### 7.2 游戏导入模块

#### 7.2.1 候选列表

扫描完成后，系统展示候选游戏列表。

字段：

- 推断游戏名称
- `.exe` 文件名
- `.exe` 完整路径
- 所在目录
- 是否已存在

交互：

- 默认勾选未重复的候选项。
- 已存在的候选项默认不可重复导入。
- 用户可以手动取消勾选不需要的候选项。
- 用户点击确认后才写入数据库。

#### 7.2.2 重复处理

重复判断规则：

- `exe_path` 是唯一键。
- 同一路径再次扫描时不重复创建记录。
- 如果已有记录被用户编辑过，扫描不得覆盖用户自定义字段。

### 7.3 游戏库模块

#### 7.3.1 游戏列表

展示所有已导入或手动添加的游戏。

要求：

- 默认按收藏优先、最近游玩时间倒序、创建时间倒序展示。
- 支持空状态展示。
- 支持刷新列表。
- 支持点击游戏查看详情。

展示字段：

- 游戏名称
- 图标或默认占位图
- 收藏状态
- 最近游玩时间
- 启动次数

#### 7.3.2 搜索

用户可以通过关键词搜索游戏。

要求：

- 搜索范围包含游戏名称和 `.exe` 文件名。
- MVP 使用普通大小写不敏感匹配。
- fuzzy search 放到后续优化。

#### 7.3.3 分类筛选

MVP 支持以下筛选：

- 全部
- 收藏
- 最近游玩

V1 可扩展标签分类。

#### 7.3.4 编辑游戏

用户可以编辑已保存的游戏信息。

可编辑字段：

- 游戏名称
- `.exe` 路径
- 工作目录
- 启动参数
- 图标路径（可选，MVP 可不开放）
- 收藏状态

校验：

- 游戏名称不能为空。
- `.exe` 路径不能为空。
- `.exe` 路径必须指向 `.exe` 文件。
- 工作目录为空时默认使用 `.exe` 所在目录。

#### 7.3.5 移除游戏

用户可以从游戏库移除游戏。

要求：

- 只删除本地数据库记录。
- 不删除用户磁盘上的游戏文件。
- 删除前需要二次确认。

### 7.4 手动添加模块

用户可以不经过扫描，直接添加一个游戏。

表单字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 游戏名称 | 是 | 用户自定义展示名 |
| `.exe` 路径 | 是 | 游戏启动程序路径 |
| 工作目录 | 否 | 默认使用 `.exe` 所在目录 |
| 启动参数 | 否 | 传递给游戏进程的参数 |

要求：

- 支持文件选择器选择 `.exe`。
- 选择 `.exe` 后自动填充默认游戏名称和工作目录。
- 保存前校验路径是否存在。
- 如果 `exe_path` 已存在，提示用户不可重复添加。

### 7.5 游戏启动模块

用户点击启动按钮后，系统启动对应游戏程序。

要求：

- 使用 Tauri 后端能力在 Windows 环境启动本地进程。
- 支持启动参数 `args`。
- 支持 working directory。
- 启动成功后记录 `last_play_time` 和 `play_count`。
- 启动失败时提示明确错误。

失败场景：

- `.exe` 文件不存在。
- `.exe` 路径不是可执行文件。
- 工作目录不存在。
- 权限不足。
- 系统拒绝启动进程。

### 7.6 收藏与最近游玩

#### 7.6.1 收藏

用户可以收藏或取消收藏游戏。

要求：

- 收藏状态持久化。
- 收藏游戏在默认排序中优先展示。
- 收藏筛选只展示已收藏游戏。

#### 7.6.2 最近游玩

系统在游戏启动成功后记录最近游玩时间。

要求：

- 最近游玩筛选只展示有启动记录的游戏。
- 按 `last_play_time` 倒序展示。
- 每次启动成功后 `play_count + 1`。

### 7.7 设置模块

MVP 设置项：

- 已保存的扫描目录列表。
- 默认扫描排除规则展示。
- 数据库位置展示。

V1 设置项：

- 自定义排除规则。
- 自定义排序方式。
- 数据导入 / 导出。

## 8. UI 需求

### 8.1 主界面布局

主界面由三部分组成：

- 顶部：搜索栏、扫描按钮、手动添加按钮。
- 左侧：筛选导航，包括全部、收藏、最近游玩。
- 中间：游戏列表或网格。

要求：

- 首屏直接展示游戏库，不做营销式首页。
- 空状态提供扫描目录和手动添加两个主要入口。
- 操作按钮需要清晰区分主要操作和次要操作。

### 8.2 游戏卡片

游戏卡片包含：

- 游戏图标或默认占位图。
- 游戏名称。
- 最近游玩时间。
- 启动按钮。
- 收藏按钮。
- 更多菜单：编辑、移除、打开所在目录。

要求：

- 启动按钮是主要操作。
- 游戏名称过长时需要省略，不得撑破布局。
- 没有图标时使用统一默认样式。

### 8.3 扫描结果弹窗

扫描结果弹窗包含：

- 扫描目录信息。
- 候选游戏数量。
- 可勾选候选列表。
- 已存在项提示。
- 确认导入按钮。

### 8.4 添加 / 编辑游戏弹窗

表单包含：

- 游戏名称
- `.exe` 路径
- 工作目录
- 启动参数

要求：

- 必填项校验。
- 路径选择器。
- 保存、取消按钮。
- 保存失败展示错误原因。

## 9. 数据模型

### 9.1 Game 类型

```ts
interface Game {
  id: string
  name: string
  exePath: string
  folderPath: string
  icon?: string | null
  args?: string | null
  workDir?: string | null
  favorite: boolean
  playCount: number
  lastPlayTime?: number | null
  createTime: number
  updateTime: number
}
```

### 9.2 ScanCandidate 类型

```ts
interface ScanCandidate {
  name: string
  exePath: string
  folderPath: string
  fileName: string
  exists: boolean
  selected: boolean
}
```

### 9.3 SQLite 表结构

```sql
CREATE TABLE games (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  exe_path TEXT NOT NULL UNIQUE,
  folder_path TEXT NOT NULL,
  icon TEXT,
  args TEXT,
  work_dir TEXT,
  favorite INTEGER NOT NULL DEFAULT 0,
  play_count INTEGER NOT NULL DEFAULT 0,
  last_play_time INTEGER,
  create_time INTEGER NOT NULL,
  update_time INTEGER NOT NULL
);

CREATE INDEX idx_games_name ON games(name);
CREATE INDEX idx_games_favorite ON games(favorite);
CREATE INDEX idx_games_last_play_time ON games(last_play_time);
```

可选配置表：

```sql
CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  update_time INTEGER NOT NULL
);
```

## 10. 技术栈

### 10.1 推荐技术栈

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| 桌面框架 | Tauri | 打包 Windows 桌面应用、访问系统能力 |
| 前端框架 | Vue 3 | 构建桌面 UI |
| 前端语言 | TypeScript | 类型约束和可维护性 |
| 构建工具 | Vite | 前端开发和构建 |
| 后端语言 | Rust | Tauri command、文件扫描、进程启动、数据库访问 |
| 数据库 | SQLite | 本地持久化游戏数据 |
| 状态管理 | Pinia | 管理游戏列表、筛选、扫描状态 |
| UI 组件 | 自定义组件或轻量组件库 | 构建桌面应用界面 |

### 10.2 技术选择说明

- Tauri 比 Electron 更轻，适合轻量本地工具。
- Rust 适合处理文件扫描、路径校验和进程启动。
- SQLite 不需要额外服务，适合本地持久化。
- Vue 3 + TypeScript 开发效率高，适合构建中小型桌面 UI。

### 10.3 关键 Tauri 能力

需要使用：

- 文件夹选择器
- 文件选择器
- 本地文件系统访问
- Tauri command
- 进程启动能力
- app data 目录读取

## 12. 非功能需求

### 12.1 性能

- 应用冷启动目标小于 1 秒。
- 扫描 1000 个 `.exe` 候选文件目标小于 5 秒。
- 扫描过程中 UI 不能卡死。
- 游戏列表 1000 条以内需要保持流畅。

### 12.2 稳定性

- 数据库读写失败需要提示错误。
- 启动游戏失败不能导致应用崩溃。
- 扫描目录失败需要跳过不可访问目录并记录错误。

### 12.3 安全性

- 应用不自动执行扫描到的 `.exe`。
- 用户必须主动点击启动才执行本地程序。
- 删除游戏记录不删除磁盘文件。
- 不上传本地路径和游戏信息。

### 12.4 本地化

- MVP 默认中文界面。
- 文案集中管理，后续可扩展英文。

## 13. MVP 验收标准

MVP 需要满足：

- 用户可以选择目录并扫描 `.exe`。
- 系统可以展示扫描候选列表。
- 用户可以确认导入候选游戏。
- 用户可以查看本地游戏列表。
- 用户可以搜索游戏。
- 用户可以手动添加游戏。
- 用户可以编辑游戏信息。
- 用户可以从列表移除游戏，但不删除磁盘文件。
- 用户可以点击启动游戏。
- 启动成功后可以记录最近游玩时间和启动次数。
- 游戏数据在关闭应用后仍然存在。
- 没有后端服务时应用可以正常使用。

## 15. 待确认问题

正式开发前建议确认：

1. 产品名称是否固定为 Game Shift。
2. MVP 是否只支持 Windows。
3. 是否确定使用 Tauri，而不是 Electron。
4. 是否需要在 MVP 支持网格视图，还是先只做列表视图。
5. `.exe` 图标提取是否放到 V1。
6. 扫描结果是否必须用户确认后才导入。建议是确认后导入。
7. 是否需要支持打开游戏所在目录。建议放入 MVP 的更多菜单。
8. 数据库是否允许后续导出和导入。建议 V1 做。
