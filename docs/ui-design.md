# Game Shift UI 设计说明

## 1. 设计方向

Game Shift 以 `方案 1` 设计稿为准，采用暗色半透明桌面游戏启动器风格：左侧导航、顶部搜索、紫色强调色、玻璃质感内容区。

产品定位：Game Shift 是 Windows 本地游戏启动器，不是后台管理系统，也不是 SaaS 仪表盘。界面应服务于快速搜索、快速启动、收藏复玩和本地游戏库维护。

核心体验优先级：

1. 搜索游戏
2. 快速添加 / 扫描游戏
3. 收藏游戏
4. 全部游戏浏览
5. 最近游玩（启动功能完成后接入真实数据）
6. 分类、设置等扩展能力

## 2. 信息架构

首页采用左侧导航 + 右侧内容区结构，不做营销页。

页面结构：

1. 左侧导航
2. 顶部搜索和操作区
3. 首页内容区
4. 收藏游戏区块
5. 全部游戏区块

### 2.1 左侧导航

左侧导航是设计稿中的固定结构，不应移除。

导航项：

- 首页
- 全部游戏
- 收藏游戏
- 最近游玩
- 分类
- 设置

当前阶段要求：

- 首页展示收藏游戏和全部游戏。
- 全部游戏切换到完整列表。
- 收藏游戏切换到收藏筛选。
- 最近游玩保留入口，但由于启动记录尚未接入，展示空状态。
- 分类和设置可以先作为占位入口。

### 2.2 顶部搜索和操作区

顶部操作区保持设计稿中的单行工具栏。

```text
[搜索游戏 / 启动程序 / 路径................] [添加游戏] [扫描目录] [刷新]
```

说明：

- 搜索框用于快速定位游戏，是主入口。
- 添加游戏用于手动添加本地 `.exe`。
- 扫描目录当前作为占位入口，后续接入目录扫描。
- 刷新用于重新读取本地数据库。

### 2.3 收藏游戏区域

收藏游戏是高频复玩入口，必须出现在首页首屏，不只藏在左侧筛选里。

展示原则：

- 有收藏时横向展示紧凑卡片。
- 无收藏时展示轻量空状态。
- 首页收藏卡片只保留启动和取消收藏。
- 编辑、删除属于游戏库维护操作，只放在全部游戏列表或完整管理列表。
- 首页里的“查看更多”进入收藏筛选。

### 2.4 全部游戏区域

全部游戏区域用于完整游戏库浏览和维护。

展示原则：

- 支持网格 / 列表视图。
- 支持搜索后展示匹配结果。
- 支持空结果状态。
- 支持卡片操作：收藏、启动、编辑、移除。

### 2.5 最近游玩区域（后置）

最近游玩依赖启动功能、`last_play_time` 和 `play_count` 的真实写入。当前阶段保留左侧入口，不在首页制造假数据。

接入条件：

- 启动游戏功能完成。
- 每次启动后能更新 `last_play_time`。
- 每次启动后能累加 `play_count`。

接入后展示原则：

- 最近游玩可以在首页增加独立区块。
- 有数据时展示 Top 5 或 Top 6。
- 按最近游玩时间倒序。
- 无数据时不展示整块区域，或只使用轻量提示。

## 3. 游戏卡片

### 3.1 信息层级

默认展示：

- 游戏图标或字母占位
- 游戏名称
- `.exe` 文件名或路径摘要
- 最近游玩时间
- 启动次数

操作层级：

- 启动是最高优先级操作。
- 收藏是高频操作，应常驻或弱常驻。
- 首页收藏卡片只展示启动和取消收藏。
- 编辑、移除是低频维护操作，只在全部游戏列表或完整管理列表展示。
- 网格模式用于视觉浏览。
- 列表模式用于密集浏览。

### 3.2 Hover 状态

卡片 hover 使用轻量动效，避免浮夸。

```css
.game-card:hover {
  transform: translateY(-2px);
  border-color: rgba(167, 139, 250, 0.4);
}
```

### 3.3 收藏状态

收藏按钮直接放在卡片上。

- 未收藏：空心图标，低对比度。
- 已收藏：实心图标，使用紫色强调色。
- 点击后使用轻微 scale 动效。
- 收藏不放进编辑弹窗。

## 4. 弹窗规范

### 4.1 新增 / 编辑游戏弹窗

新增和编辑弹窗应轻量、明确，视觉上匹配暗色玻璃拟态界面。

字段顺序：

1. 启动程序
2. 游戏名称
3. 工作目录
4. 启动参数

路径字段策略：

- 启动程序只读，只能通过文件选择器选择 `.exe`。
- 工作目录只读，只能通过文件夹选择器选择。
- 选择 `.exe` 后自动推断游戏名称和工作目录。
- 游戏名称如果用户已填写，不自动覆盖。

以下能力后置：

- Icon Preview
- Category
- Tags
- exe 图标提取

### 4.2 删除确认弹窗

删除确认必须明确说明不会删除本地文件。

文案建议：

```text
确认从游戏库移除「Game Name」？
只会删除 Game Shift 中的记录，不会删除本地磁盘上的游戏文件。
```

视觉原则：

- 不使用大面积红色。
- 使用弱红图标背景。
- 主危险按钮使用红色。
- 路径摘要可以放在说明下方。

## 5. 视觉规范

### 5.1 色彩方向

以设计稿的紫色暗色启动器为准。

建议主题变量：

```css
:root {
  --bg: #17131f;
  --bg-deep: #0f0d14;
  --panel: rgba(32, 28, 41, 0.58);
  --surface: rgba(255, 255, 255, 0.07);
  --surface-hover: rgba(255, 255, 255, 0.11);
  --border: rgba(255, 255, 255, 0.1);
  --text: #f5f2ff;
  --text-muted: rgba(245, 242, 255, 0.68);
  --accent: #8b5cf6;
  --accent-strong: #a78bfa;
  --accent-soft: rgba(139, 92, 246, 0.24);
  --danger: #fb7185;
}
```

### 5.2 圆角

- 页面导航 / 面板：8px
- 游戏卡片：8px
- 按钮：8px
- 输入框：8px
- 弹窗：8px

### 5.3 背景

设计稿包含暗色游戏氛围背景。当前阶段不引入具体游戏图版权素材，先使用暗色渐变和半透明玻璃质感模拟。后续如需要更接近设计稿，可引入项目自有背景图或生成背景图。

### 5.4 字体密度

- 页面标题：18-22px
- 区块标题：18-20px
- 卡片标题：14-16px
- 列表文字：12-13px
- 辅助信息：11-12px

整体密度偏桌面工具型，不做大字号营销风格。

## 6. 动效规范

只使用 CSS transition，不依赖动画库。

动效范围：

- 卡片 hover 轻微上移。
- 按钮点击轻微 scale。
- 弹窗打开淡入 + 轻微上移。
- 收藏点击使用按钮点击反馈。

## 7. 当前阶段边界

当前 UI 阶段只做可落地的真实功能界面。

已纳入：

- 左侧导航布局
- 紫色暗色主题
- 顶部搜索和操作区
- 收藏游戏首页区块
- 全部游戏区块
- 添加 / 编辑 / 删除弹窗视觉
- 卡片 hover 和按钮点击反馈

暂不纳入：

- 真实游戏封面
- 真实游戏启动
- 最近游玩首页区块
- 分类管理
- 设置页
- 背景图资产
